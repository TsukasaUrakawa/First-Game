# UIの配置と重なりの確認

画面上部は用途ごとに段を分けています。棚を拡大したときに、
「中断」などが「並びをチェック」に重なることを防ぎます。

- 右上の`MenuButtonRow`に「中断」「設定」「あそびかた」をまとめ、
  `HorizontalLayoutGroup`で間隔を保ちます。通常は右端から24、上から24です。
  本一覧と取り出し確認では、一覧の「閉じる」の左側へ移動し、上から36の位置で上辺を揃えます。
  表示するボタンが減った場合は右揃えで詰めます。
- 「部屋に戻る」は左上のままです。棚の操作バー`ShelfActionPanel`は上から112、
  高さ128の領域に置き、システム用ボタンと段を分けています。
- 案内パネルは、部屋では上から180、棚の拡大中は264に表示します。
  棚の操作バーとの間に24の余白を残します。本一覧ではヘッダーの中央付近です。
- 棚一覧の見出し・色名・冊数・下部案内は、文字の高さを収める領域を確保しています。
  最終行と下部案内の間にも余白を設けています。
  一覧は左上から24の位置に置き、段ボールの描画範囲と重ならないようにしています。
  ボタンの大きさと2列×4段の並びは維持しています。
- 取り出し確認のカードは中央より24下げ、上の案内と離しています。
  本一覧の補足と残り冊数は、案内の表示領域まで伸びない幅にしています。

数値はCanvasの基準座標です。メニューの表示条件と位置は`GameplayUIController`、
案内の位置は`BookPlacementTutorial`で更新します。個別のボタンに画面座標を追加する場合も、
上部メニュー・棚の操作バー・案内が同時に表示される状態を確認してください。

## 棚の見える範囲

`CameraController`は、棚の拡大率を16:9の見た目を基準に調整します。
4:3など横幅が狭い画面では、棚の左右が切れないよう縦の表示範囲を広げます。
拡大中に画面比率を変えた場合も追従します。16:9以上の横長画面では、
設定した拡大率を使います。部屋へ戻ると、本棚をUIの空き領域へ収める位置とサイズへ戻します。
部屋の段ボールも同時に配置し直し、画面比率を変えても棚選択と手持ちに重ならないようにします。

## 点検

`Tests/UILayoutOverlapSmoke.cs`は、表示中のボタン・文字・主要パネルを列挙し、
画面外へのはみ出し、互いの重なり、ボタン中央と四隅への入力を調べます。
本一覧はスクロールのマスク範囲だけを調べ、意図的に重ねたモーダルの背後は除外します。
文字の判定には、透明なSDFの余白ではなくグリフの寸法を使います。
部屋では段ボールのRendererの境界を画面へ投影し、見えている全範囲とUIの重なりも調べます。
中央のクリックが通る場合でも、上端が隠れていれば検出します。

点検結果の`issueCount`が0、`issues`が空であることを確認します。
件数は表示中の要素と保存表示のタイミングで変わります。
`Tests/ShelfReachabilitySmoke.cs`では、8棚・140か所が画面内にあり、
UIで隠れず配置できることを調べます。
`Tests/BoxReachabilitySmoke.cs`では、段ボールと棚一覧の余白、複数のCollider上の
画面座標でUIにクリックを遮られないことを調べます。

1920×1080、1366×768、1024×768で確認しています。
タイトル（保存あり／なし）、新規開始確認、部屋と棚（案内あり／なし）、
本一覧（案内あり／なし／箱が空）、1冊と9冊の取り出し確認、9冊の手持ち、
完成図、中断、保存失敗表示、設定、クリアを含む22状態を点検しています。
操作・保存の退避と復元の手順は`Tests/README.md`を参照してください。
ブラウザ上の実際の操作と描画は、WebGLビルドで別途確認します。
